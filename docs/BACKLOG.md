### E9 Sharing

Researched 2026-10-25 (105-agent verified web research; report in the S9.1 PR). Direct posting is closed or hostile on four of the six networks: Facebook removed `publish_actions` in 2018 and points at its Share dialog; X bills the developer $0.20 per API post containing a URL (pay-per-use since February 2026, Basic and Pro closed to new signups); LinkedIn's Community Management API is for registered businesses only, and its self-serve `w_member_social` needs a client secret a desktop binary can't keep; Bluesky's intent takes `text` only, but its OAuth is open. Slack and Discord incoming webhooks are a single POST whose URL is the credential. So: browser intents for the networks, webhooks for the chat tools, and a user-defined URL template for everything else (Feedly's Custom Sharing is exactly that, and its one complaint was that you get a single template). Nothing here awaits HTTP or a child process on the UI thread: intents go through `open_in_browser` (spawns `xdg-open`, waits on its own thread, as `O` does today), webhooks through the web worker. `s` is star and `S` the starred view, so share takes another key, `p` (post) unless a better one turns up.
